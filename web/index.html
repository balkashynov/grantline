02 / USE YOUR OWN CONFIGURATION

From overlap state to a reviewable diff.

  1. Keep both identities in place.

    Follow MongoDB’s migration guide through the overlap phase. Grantline does not apply changes.

  2. Extract only the comparison fields.

    The local importer reads Terraform state JSON, follows organization-level identities and their project assignments through nested modules, and omits secret fields.

  3. Review, then test the application.

    Fix missing assignments. Review deliberate widening. Confirm unmanaged resources and the organization IP setting. Test actual API operations before retiring anything.

LOCAL CLI · GO 1.26+
go build -o grantline ./cmd/grantline

# State can contain secrets. Keep it local.
terraform show -json > state.json

./grantline import \
  -state state.json \
  -from mongodbatlas_api_key.legacy \
  -to mongodbatlas_service_account.replacement \
  -require-ip-list true > comparison.json

./grantline compare -input comparison.json

Use the actual organization setting for -require-ip-list. Unknown policy produces an incomplete result.

03 / HOW IT EARNS THE RESULT

Set arithmetic, with concrete witnesses.

01

Normalize

Scope each role to an organization or project. Turn CIDRs into sorted, disjoint integer intervals. Duplicate and overlapping entries collapse.

02

Subtract

Compute old minus new and new minus old. A linear sweep finds exact differences without enumerating IPv4 or IPv6 addresses.

03

Explain

Emit canonical CIDRs, exact address counts and a witness for every changed range. The CLI and browser use the same Go implementation.

Read the validation and limits ↗

What a match means.

The supplied role assignments and address sets match within this snapshot. It does not prove effective authorization, discover unmanaged access, validate credential rotation, or establish that deleting the old key is safe.

Supported import: terraform show -json state, organization API keys and service accounts, their project-assignment resources and organization access-list resources. Plans and unsupported identity shapes are rejected. IPv6 arithmetic is supported; Atlas acceptance of those addresses is not tested.
